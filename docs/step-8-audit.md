## 2. Adjudication of the 42 overturned claims

**Method.** Two fresh adjudicators, about 21 claims each, judged every overturned claim against the current text and its current page. They did not see the spot-check verdicts or the ledger. Each read the page with `scripts/q.ts` and returned a category, a one-sentence reason and the verbatim AWS sentence it relied on. The adjudicators are fresh agents of the same model family, so their independence is partial. The category counts were taken from the adjudicators' returned records; I did not re-judge them one by one.

**Gate.** Errors are (a) + (b) = 1 of 172. The limit is 5 (3%). The gate passed, so no re-audit ran.

**Fixes.** Every (c) claim was fixed by rewording to what the page says, or by adding a verbatim quote that states it. The (d) claims were already fixed; they were confirmed against the current text. The 73 changed claims were re-checked by fresh checkers in rounds. Round 1 confirmed 60 and found 13 unsupported. Rounds 2 to 4 fixed those and found a few more, which were also fixed; the last fix (`q:blueprint-hall-010`) was not rechecked by a fresh checker (section 6).

**Category (b), the one error:** `q:refinery-008`. The Athena distractor said Spark code would be rewritten. The current Athena Spark page says that running Spark on Athena means submitting Spark code for processing. The distractor reason was corrected. The key (EMR) stands, because only the EMR page names S3 and DynamoDB data movement.
